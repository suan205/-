如何开始写自己的页面？

  1. 先点“测试核心流程”，确认注册、登录、/api/auth/me 都能通。
  2. 在预留的空文件 web/index.html 中编写网站首页（文件不存在时再新建），放置“登录”“注册”链接，分别指向同目录的 login.html 和 register.html。
  3. 再新建 web/login.html、web/register.html、web/dashboard.html；不要直接复制 test.html 当成品。
  4. 自行完成页面结构、样式和交互，CSS 和 JS 文件也放在 web/ 下；保留现有测试页和工具文件。
  5. 使用模块脚本复用 loginUser、registerUser、getCurrentUser。在同级 HTML 的 <script type="module"> 内从 ./js/api.js 引入；若写在 web/js/login.js 中，则从 ./api.js 引入，并在 web/login.html 用 <script type="module" src="./js/login.js"></script> 加载。
  6. 保持 start.bat 的后端窗口运行，通过当前服务的 /web/ 地址进入首页（默认 http://127.0.0.1:8000/web/，改端口时同步替换）；不要双击 HTML 或使用 Live Server。修改 HTML/CSS/JS 后保存并刷新浏览器即可，无需重启服务。
  7. 登录 / 注册成功后，将函数返回值记为 auth，用 localStorage.setItem("access_token", auth.access_token) 保存 Token，再跳到 dashboard.html。API 工具不会自动保存自定义网站的 Token 或跳转页面。
  8. 在 dashboard 中读取 Token，调用 getCurrentUser(token) 获取用户信息；没有 Token 或返回 401 时清除本地 Token 并返回登录页。退出登录时删除 access_token 并跳回登录页。前端跳转只控制页面体验，用户数据由后端鉴权保护。

测试页文件：web/test.html；测试页逻辑：web/js/test.js；通用 API：web/js/api.js。

测试页只用来调接口，不要把它直接当成最终登录页。 所有页面都在同一个服务下。测试台使用独立的 Token 存储，不会覆盖你的网站登录状态。当 web/index.html 有内容时，下次运行 start.bat 会自动打开 /web/；文件不存在或为空时打开 /test。服务运行期间，写好首页后可直接访问 /web/。
